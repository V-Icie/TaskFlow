# Пояснення архітектурної діаграми TaskFlow

Файл схеми: [`architecture_diagram.png`](architecture_diagram.png).

## Наявні блоки (суцільні контури)

1. **Client (браузер):** сторінка HTML/CSS/JavaScript показує кнопку **Load items**. Після натискання `public/app.js` робить HTTP-запит `fetch('/items')`.
2. **Backend (Node.js/Express):** `src/server.js` запускає сервер, `src/app.js` приймає `GET /items` і звертається до модуля роботи з БД.
3. **Database (SQLite):** `src/db.js` створює таблицю `items (id, name)` за потреби, читає тестові записи і повертає їх серверу. **Браузер не підключається до бази напряму.**

## Зв'язки

- **Client → Backend:** HTTP GET `/items`, відповідь JSON.
- **Backend → Database:** SQL-запит до локальної SQLite; результат повертається назад через API до клієнта.

## Майбутні блоки (пунктирні контури)

- **Task Management:** CRUD, статуси й валідація завдань; заплановано на наступні практичні.
- **Authentication:** входи та ролі користувачів; концептуальний майбутній модуль, ще не реалізований.
- **Categories:** групування й фільтрація завдань; запланований модуль.

**Примітка:** це логічні модулі майбутнього застосунку, а не окремі мікросервіси. На поточному етапі архітектура — один Express-бекенд і одна SQLite-база.
