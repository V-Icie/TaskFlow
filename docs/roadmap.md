# Roadmap розвитку TaskFlow

**Практична №2.** Умовний план на наступні чотири навчальні тижні після базового прототипу. Номери тижнів відповідають етапам проєктування, а не календарним датам; фактичне виконання може бути прискорене.

| Тиждень | Ціль | Основні дії | Критерій готовності |
|---|---|---|---|
| 1 (наступний етап, практика №3) | Змоделювати предметну область | Піддомени «Завдання», «Користувачі», «Категорії»; словник 5–10 термінів; context map; моделі Task, User, Category | `docs/domain/` та класи моделей додано до репозиторію |
| 2 (практика №4) | Створити контракт і CRUD API | `POST /tasks`, `GET /tasks`, `GET /tasks/{id}`, `PATCH /tasks/{id}`, `DELETE /tasks/{id}`; OpenAPI; DTO; валідація; 2 тести | CRUD працює й узгоджений із `docs/api/openapi.yaml` |
| 3 (практика №5) | Підвищити стійкість API | Idempotency-Key, X-Request-Id, 429 + Retry-After, таймаути, retries, degraded mode | Демонстрація безпечного повтору POST та керованих помилок |
| 4 (практики №6–7) | Підготувати розгортання та перевірки | Dockerfile, `docker-compose.yml` для frontend/API/PostgreSQL, CI в GitHub Actions | Контейнери стартують локально; CI тести проходять у GitHub |

## Наступні напрямки, поза цими чотирма тижнями

- Практична №8: метрики, логи та трейси через OpenTelemetry і Grafana.
- Практична №9: теоретична схема розгортання Kubernetes.
- Практична №10: навчальне розгортання в Minikube.
- Авторизація — майбутня опція, не обов'язкова частина поточної чотиритижневої дорожньої карти.

## Залежності

1. Модель домену визначає API-сутності і правила перевірки.
2. REST API потрібен для демонстрації повторів та обробки помилок.
3. Робочий застосунок і тести потрібні для контейнеризації та CI.

## Ризики та резервний план

- **Docker Desktop не запускається:** завершити №3–5 локально без Docker, відкласти контейнеризацію до відновлення Engine.
- **Брак часу:** спочатку завершувати мінімальні обов'язкові вимоги та фіксувати робочу версію кожного етапу.
- **Командні вимоги:** узгодити з викладачем індивідуальний формат, якщо інші учасники недоступні; не підміняти реальні pull requests фіктивними.
