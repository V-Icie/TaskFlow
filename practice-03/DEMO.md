# Google Meet: сценарій захисту №3 (орієнтовно 4–6 хвилин)

1. Відкрити GitHub → `docs/domain/entities.md`; пояснити основну предметну область і три піддомени.
2. Відкрити `docs/domain/context_map.png` та показати три bounded contexts. Identity надає ідентифікатори власника, Categories — категорій, Tasks відповідає за статус і назву справи. Стрілки логічні, а не реальні HTTP-виклики.
3. Відкрити `docs/domain/glossary.md`, пояснити `Item` vs `Task`, `Category` vs `Status`.
4. У VS Code показати `domain/Task.js`: поля, `rename()`, `complete()`, `reopen()`, `assignCategory()`.
5. У терміналі з кореня проєкту запустити `npm test`; показати тести моделей та БД. За необхідності окремо `node --test tests/domain.test.js`.
6. Пояснити: старий `GET /items` з №1 не змінено, а повноцінний `/tasks` API з'явиться у №4.

**Коротке пояснення:** «Ми моделювали TaskFlow за бізнес-функціями: користувачі, завдання й категорії. Для кожної частини визначили власні сутності, межі, спільний словник термінів і мінімальні класи з правилами. Наразі це прототип домену без підключення до БД; CRUD реалізуємо наступним етапом».

**Для індивідуальної роботи:** сказати «я розробив», а не «ми з командою». GitHub-частину PR потрібно демонструвати лише якщо вона реально виконана і формат узгоджений.
